# 滑鼠與觸控板分開的捲動方向

macOS 的「自然捲動」是滑鼠和觸控板共用一個設定。設定 → 滑鼠與觸控板的「滑鼠滾輪反向」「觸控板反向」攔截捲動事件，把選了反向的那一種反過來。程式在 `Services/ScrollDirection.swift`。

## 原則

- 兩個開關都關掉時完全不攔截
- 打開時只在捲動的瞬間處理事件，不輪詢
- 需要「輔助使用」權限；權限的保留靠固定的簽章（見 [release-and-signing.md](release-and-signing.md)）
- 設定頁顯示的是實際狀態：「運作中」表示正在攔截，「啟動中…」表示有權限、還沒開始，沒有權限時顯示橘色的說明與「打開輔助使用設定」

## 架構

| 角色 | 執行緒 | 負責 |
|---|---|---|
| `ScrollDirection` | 主執行緒 | 依設定開始或停止；每 5 秒檢查一次攔截的狀態；權限與狀態改變時通知設定頁 |
| `ScrollTap` | 自己的執行緒（user-interactive 優先權） | `CGEvent.tapCreate` 建立攔截，跑自己的 run loop；判斷裝置、改寫事件 |
| 手指計數 | 主執行緒 | 用 `NSEvent.touches(matching:)` 數觸控板上的手指，寫入最近一次兩指以上的時間 |

- 攔截不放在主執行緒：主執行緒忙著畫面板或取樣時，回呼太慢會被系統以「回應逾時」暫停。放在自己的執行緒後，捲動不用等主執行緒
- 攔截的事件只有捲動（`scrollWheel`）與觸控板手指事件（`NSEvent.EventType.gesture`，數值 29）
- 手指要在主執行緒數：在其他執行緒用 `NSEvent(cgEvent:)` 讀觸碰資訊永遠是 0 指
- 跨執行緒的資料只有設定與「最近一次兩指的時間」，用鎖保護；判斷裝置用的其他狀態只在攔截執行緒使用

## 判斷是滑鼠還是觸控板

`ScrollTap.classify` 依序判斷：

1. **不連續的捲動（一般滾輪）一定是滑鼠**，而且不改動觸控板那邊的判斷。觸控板放手後的慣性還在滑時轉一下滾輪，之後的慣性仍算觸控板
2. **慣性事件**（momentum phase 不是 0）沿用同一段手勢的判斷
3. **新的一段手勢**（scroll phase 是 1 或 128，或沒有階段的連續捲動）：最近 0.3 秒內觸控板上有兩指以上就算觸控板
4. **手勢進行中**（scroll phase 2、4、8）：只會從滑鼠改成觸控板、不會反過來。主執行緒慢一點、一時沒數到手指，也不會中途改判

所以 Magic Mouse 的單指捲動算滑鼠（連續，但觸控板上沒有手指）。

## 怎麼反向

捲動量除了公開的欄位，還有沒有公開文件的 175～178（小數欄位）。實測 macOS 13 與 27 的觸控板事件都有：176／178 是垂直，175／177 是水平。網頁（WebKit）用它們算放開手指後的慣性。

| 欄位 | 型別 |
|---|---|
| `DeltaAxis1/2`（行數）、`PointDeltaAxis1/2`（像素） | 整數 |
| `FixedPtDeltaAxis1/2`（精細值） | 小數 |
| 175～178（原始捲動量） | 小數 |

- **一般滾輪**：直接改原本的事件，把整數欄位、精細值與 175、176 取負號
- **連續捲動（觸控板、Magic Mouse）**：改用新造的事件取代原本的事件，回呼回傳新事件（`passRetained`）。177、178 是系統從事件附帶的原始觸控資料算出來的，改不掉；寫入它們還會把 175、176 重設回原值。只改其他欄位時，拖動的方向反了、慣性卻照原方向，網頁就會一直往回彈。新造的事件沒有那份觸控資料，所有捲動量（包括 175～178）都是取負號後的值
- 新事件照抄原本的位置、修飾鍵、時間，以及連續與否、手指階段、慣性階段、捲動次數、`InstantMouser`，與慣性相關、沒有公開文件的 137、173

## 保持運作

- 系統以「回應逾時」或「使用者輸入」暫停攔截時，回呼會收到通知，立刻重新打開
- 系統在睡眠喚醒、權限變動時可能暫停甚至作廢攔截，而且不一定通知。主執行緒每 5 秒檢查一次：被暫停就重新打開，已作廢就停掉重建；沒有在跑、但已經有權限（例如剛重新允許「輔助使用」）就開始
- 開始、停止、暫停、重建與權限改變一律寫進系統記錄（很少發生，不影響效能）

## 權限

- 攔截並改寫事件需要「輔助使用」。macOS 用 App 的簽章身分（designated requirement）記住允許；v1.7.4 起每個版本用同一張憑證簽，更新後權限仍然有效
- v1.7.3 以前是 ad-hoc 簽章，每個版本的身分都不同。清單裡的開關看起來還開著，對新版本卻沒有作用，要先移除再加一次。從 v1.7.3 以前更新上來時要做最後一次

## 記錄與除錯

- 系統記錄：`/usr/bin/log stream --predicate 'subsystem == "com.kuan.batterymonitor" AND category == "scroll"'`（zsh 裡 `log` 是內建指令，要寫完整路徑）
- `defaults write com.kuan.batterymonitor scrollDebug -bool true` 後重新打開 App：另外記下每個捲動事件被認成觸控板或滑鼠、手指數、各欄位改寫前後的值。查完用 `defaults delete com.kuan.batterymonitor scrollDebug` 關掉
- `defaults write com.kuan.batterymonitor scrollRebuild -bool false`：連續捲動改回直接改原本的事件，用來比較兩種做法（網頁會往回彈）
- `--selftest-scroll`：造出滾輪、觸控板、慣性與 Magic Mouse 的捲動事件，走同一段判斷，印出哪些會反向、175～178 有沒有跟著反向；也測試滾輪夾在觸控板慣性中間的情況。不需要權限

## 驗證過的情況

- macOS 27（M1 MacBook Air）：觸控板反向後網頁不往回彈；觸控板慣性中轉滾輪，滾輪照滑鼠的設定、慣性照觸控板的設定；用同一張憑證重新編譯安裝三次，「輔助使用」都保留，啟動後立刻開始攔截
- macOS 13（2015 MacBook Air）：觸控板事件同樣帶著 175～178；改用新造事件後的版本還要再實測
