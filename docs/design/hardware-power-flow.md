# 電力流向與硬體功耗

面板主頁的「電力流向」畫出變壓器、系統、電池之間的瓦數；點「系統」展開成螢幕背光、晶片運算、其他，點「晶片運算」再展開 CPU／GPU／ANE。這份文件說明數字從哪裡來、怎麼對齊、什麼時候取樣，以及哪些情況寧可不顯示。

## 原則

- 只顯示真的量到的值。缺值顯示「—」，第一次取樣顯示「取樣中」，不用 0、百分比或螢幕亮度冒充功耗
- 「其他」是差值估算，介面上明說；對不起來（取樣不同步、差值為負）時不畫出假的閉合分流，只保留系統總功耗
- 晶片運算是取得的 CPU、GPU、ANE 合計，不代表完整 SoC 功耗，也不含外接螢幕
- 讀取不需要管理員權限；只有使用者自己打開「管理員 CPU 取樣」時，CPU 才改用 `powermetrics`
- 面板關閉時不取樣、不播動畫

## 三層介面

`PanelState.powerFlowLevel` 有三層：`overview`（變壓器、系統、電池）、`components`（背光、晶片、其他）、`chip`（CPU、GPU、ANE）。面板寬 380 pt，三層用切換的方式顯示，不把所有節點擠在同一排；每一層都有返回按鈕，節點是真正的按鈕，鍵盤與 VoiceOver 都能操作。機型本身沒有的項目（沒有 ANE 通道、沒有背光感測器）直接不畫，不算缺值。每一項都可以在設定 → 顯示項目隱藏；隱藏晶片運算後就不能再展開第三層。

省電模式改用 `StaticPowerFlowView`（v1.0.0 的靜態圖示與箭頭），不畫流帶、不播動畫。

## 電力總覽：變壓器、系統、電池

| 數字 | 來源 |
|---|---|
| 變壓器輸入 | SMC `PDTR` |
| 系統耗電 | SMC `PSTR` |
| 電池功率 | 變壓器輸入 − 系統耗電（缺少任一路時改用 IORegistry 的電壓 × 電流） |

- **三個數字一定對得起來**：電池功率由另外兩個推算，不另外讀。SMC 的 `PPBR` 在部分機型上和實際充放電功率不符，完全不用
- **對齊取樣時間**：兩個感測器都每秒更新，但 `PSTR` 比 `PDTR` 慢一次更新，同時讀的兩個值直接相減有約 ±4 W 的雜訊。所以系統耗電配對 1 秒前讀到的變壓器輸入；更新頻率慢於每秒時，每次更新前 1 秒先預讀一次變壓器輸入。電池閒置時誤差由約 4 W 降到 0.00 W
- **剛拔電**：`PDTR` 可能殘留舊值，只在系統確認接著電源時才計入輸入；插拔通知後在 1、3、6 秒各重讀一次
- **是否在充電**：電池晶片的「充電中」旗標會停在舊值（M1 實測充入約 14 W、電量持續上升時，仍有十幾秒回報未充電）。有 SMC 即時功率時以功率為準：充入 3 W 以上算充電、0.5 W 以下算沒在充，中間才看晶片旗標；到達充電上限後要兩者都同意才算充電。Intel 快要充滿時推算的電池功率可能是小負值，這時晶片明確回報在充電、電流為正就以晶片為準
- **顯示穩定**：接著電源時，充電中／已達上限／未充電之間的切換要持續 10 秒才更新；沒有充電上限時，短暫降到 99%／98% 仍維持「已充飽」。接著電源但沒在充時，電池功率在 ±2 W 內畫成由變壓器直接供電；供電不足、電池真的在放電時照實畫出電池一起供電
- **剛插電**：Intel 的充電器要十幾秒才開始充。插上電源 30 秒內說明改成「剛接上電源」，流向圖先不畫電池供電

## 硬體細項

`HardwarePowerReader` 每次取樣讀一份 `ComponentPowerSample`，在背景的 `HardwarePowerWorker`（actor）上執行，不卡主執行緒：

| 項目 | 來源 |
|---|---|
| 系統總功耗 | SMC `PSTR`，和上一次取樣平均，對齊晶片能量的時間窗；沒有 `PSTR` 時用 IORegistry 的 `SystemLoad` |
| 螢幕背光 | SMC `PDBR` 或 `PBwo`（同樣和上一次平均）。兩個都沒有的機型（例如 M1 MacBook Air）不顯示背光，「其他」改為「其他（含螢幕）」 |
| CPU／GPU／ANE（Apple 晶片） | `IOReportReader` 動態載入 IOReport，訂閱 Energy Model 的累積能量；`EnergyDelta` 依單位（J、mJ、µJ、nJ）換算後除以實際取樣時間 |
| CPU／內顯（Intel） | SMC `PCPC`／`PCPG` |
| CPU（管理員 CPU 取樣） | `AdminCPUSampler` 透過系統服務讀 `powermetrics`，取代 IOReport 的 CPU 值 |

- 第一次取樣只建立能量基準，之後才有瓦數；取樣窗超過 12 秒（最慢的更新頻率 10 秒再留誤差）就丟掉重來
- 部分機型（M1、M2 Pro）的 CPU 能量計數不更新：能量差為 0 時顯示 0 W，缺通道或無效讀值才是缺值
- 每個值都要是 0～500 W 的有限數字，否則當成缺值

`PowerBreakdown.make` 把系統總功耗和細項合成畫面要的結果：

| 狀態 | 條件 | 畫面 |
|---|---|---|
| `available` | 細項齊全、時間窗對齊、差值 ≥ 0 | 其他 = 系統 − 背光 − 晶片 |
| `sampling` | 剛開始、還在建立能量基準 | 「取樣中」 |
| `incomplete` | 缺了某些細項 | 缺的顯示「—」；能估算時改標「未分類（估算）」，並註明包含未取得的晶片功耗 |
| `inconsistent` | 時間窗對不上，或差值為負 | 「取樣不同步」，不算其他 |
| `stale` | 樣本超過 3 秒沒更新 | 「等待新的功耗樣本」 |

## 取樣的生命週期

- 只在主面板開著時取樣，間隔就是更新頻率（預設每秒）。關閉面板、換到智慧充電頁或系統睡眠就停止並釋放 IOReport 訂閱；重新打開或喚醒後重建基準
- `SamplingGate` 用世代編號管理：停止或重開時世代加一，舊世代的結果一律丟掉，關閉面板後不會有晚到的結果寫回畫面；同一時間只有一次取樣在跑
- 選用的管理員 CPU 取樣跟著同一個開關：面板關閉就斷線，`powermetrics` 立即停止

## 動畫

- 流帶由 Core Animation 合成，不逐幀更新 SwiftUI。光點每 3.6 秒走一輪，三道光點相隔 1.2 秒
- 數值或曲線更新只改 mask，既有動畫的 `beginTime` 不變，數字每秒更新時光點不會重新起跑；只有拓撲改變（多出或少了一條線路）才重建
- 帶寬依有效功耗決定；缺值不畫流帶，0 W 不播光點
- 系統開了「減少動態效果」時只畫靜態的流帶；省電模式改用靜態圖

## 驗證

- `Scripts/test-power.sh`：能量單位換算、首樣本、時間回捲、計數重設、缺通道、重複通道（`ComponentPowerTests`）；完整分流、缺值、負差值、過期、取樣世代與重疊（`PowerBreakdownTests`）；數值更新不重設動畫相位（`AnimationTests`）；插拔電源、充到上限、供電不足時的狀態切換（`PowerSourceTests`）
- `--dump-hardware` 每秒印一筆硬體功耗，`--selftest-hardware` 確認展開晶片、換到智慧充電頁時取樣會停止與恢復
- 實測機型：

| 機型 | 系統總功耗 | 背光 | GPU | CPU | ANE |
|---|---|---|---|---|---|
| M2 Pro | ✓ | ✓ | ✓ | 0 W（計數不更新）；管理員 CPU 取樣可讀到 | 閒置時 0 W |
| M1 MacBook Air | ✓ | 沒有感測器，算在「其他（含螢幕）」 | ✓ | 0 W（計數不更新）；管理員 CPU 取樣可讀到 | 沒有通道，不顯示 |

Intel 的 CPU／內顯功耗（`PCPC`／`PCPG`）在 2018 Mac mini 與 2015 MacBook Air 實測讀得到。
