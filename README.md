# 電池與系統監控 macbookBatteryMonitor

macOS 選單列的電池與系統資訊 App。MacBook 上選單列直接顯示電量，點開就能看到剩餘時間、健康度、電力流向（可展開到各硬體的耗電）、可直接拖動調整的充電上限、智慧充電、歷史曲線、今日回顧、耗電排行，以及藍牙鍵盤、滑鼠、耳機等周邊設備的電量；桌上型 Mac（Mac mini、iMac、Mac Studio 等）改為顯示系統耗電。另外可以開啟 CPU／GPU（含風扇與溫度）、記憶體、磁碟（含外接磁碟）、網路的系統監控模組。

- **一個 App 適用所有 Mac**（v1.7.1 起）：Apple 晶片與 Intel、MacBook 與桌上型 Mac 都用同一個下載檔，自動判斷要顯示電池還是系統耗電；macOS 12、13 另有舊系統版本
- **系統監控可開可關**（v1.7.1 起）：第一次啟動時選「只看電池」或「電池＋系統監控」，之後在設定 → 系統監控隨時切換；關閉時四個模組都不取樣，和以前的電池版一樣省電
- **充電上限滑桿**：在面板電量下方的資訊卡直接拖動調整 macOS 的充電上限（80–100%），與系統設定裡的充電上限是同一個設定、兩邊同步；不需要管理員權限（v1.6.0 起）
- **智慧充電**（v1.7.1 起）：指定「幾點前充到幾 %」（1／2／3 小時後、自訂時間或每週排程），平常維持保養上限，算好時間才讓 macOS 充到目標，結束後還原原本的上限
- **充電夥伴**（v1.7.1 起）：充電上限滑桿左邊是一隻會呼吸、會搖尾巴的貓咪，充電時躺在發光的充電墊上；也可以換成跟著充電狀態換表情的電池夥伴，或電量條。不能調整充電上限的 MacBook（例如 Intel）一樣在面板上方顯示，只是沒有滑桿
- **今日回顧**（v1.7.1 起）：今天用掉、補回多少電量，接電幾次，用電池多久、最長一次多久
- **不會偷偷控制充電**：只有你拖動充電上限滑桿（等於在系統設定裡調整），或你設定了智慧充電時，才會調整 macOS 的充電上限；實際停在上限由 macOS 控制。預設不需要管理員權限，只有選用的「管理員 CPU 取樣」或智慧充電的「精準喚醒」才要授權
- **每秒更新**：選單列與面板上的資訊預設每 1 秒刷新一次，可在設定改成每 2、5、10 秒；面板關閉時 CPU 約 0.2%（只看電池）、約 1%（四個系統監控模組全開），不會阻止系統睡眠
- **省電模式**：電力流向改用靜態圖示、更新頻率至少每 2 秒、充電夥伴不播放動畫；可以只在使用電池時啟用（v1.7.1 起）
- **自己選顯示項目**：電力流向細項（螢幕背光、晶片、CPU／GPU／ANE）與詳細資訊欄位可以個別隱藏；機型讀不到的 ANE、螢幕背光會自動隱藏
- **一鍵更新**：有新版本時在設定按一下就下載、驗證並換上新版（v1.5.0 起）；發現新版本時會發通知，可以關閉（v1.7.1 起）；手動檢查時也能找到 Beta 測試版，安裝前會再確認一次（v1.7.1 起）
- **不需要 Xcode**：只要 Command Line Tools 就能編譯

### Intel Mac

v1.7.1 起支援 Intel Mac（通用版需要 macOS 14 以上，大約是 2018 年以後的機型；更舊的用舊系統版本），在 2018 Mac mini（Intel Core i5-8500B、macOS 15）實測：

- **溫度**：CPU 用各核心的 SMC 溫度鍵（`TC1C` 起；沒有的核心回報 -127 會被過濾），讀不到時改用 PECI／die／proximity（`TCXC`、`TC0F`、`TC0P`）；內顯 `TCGC`、獨立顯卡 `TG0D`／`TG0P`；SSD `TH0a`／`TH0b`；MacBook 電池 `TB0T` 系列
- **CPU／內顯功耗**：SMC 的 `PCPC`／`PCPG`（有號 8.7 定點數），不需要管理員密碼，所以 Intel 不顯示「管理員 CPU 取樣」
- **GPU 記憶體**：Intel 內顯讀 `inUseSysMemoryBytes`，負載時偶爾出現的溢位值（超過實體記憶體）會丟掉
- Intel 不支援從 App 調整充電上限，所以沒有充電上限滑桿與智慧充電；面板上方一樣有充電夥伴，點一下可以換外觀
- Intel MacBook 在 2015 MacBook Air（macOS 13，用舊系統版本）實測：電量、電壓、電流、循環次數與容量和 `pmset`、`ioreg` 一致，CPU、電池溫度、風扇與 CPU／內顯功耗都讀得到。健康度（最大容量）與變壓器即時電壓、電流是 macOS 在這台沒有提供，顯示「—」，可以參考容量推算

### 周邊設備

面板下方的「周邊設備」分頁列出連線中的藍牙鍵盤、滑鼠、觸控板與耳機電量（AirPods 等在同一行並排顯示「左」「右」「盒」三個電量，v1.7.1 起）。羅技、Razer 等非 Apple 的藍牙低功耗滑鼠、鍵盤也會顯示（v1.6.2 起，需要允許藍牙權限，第一次啟動時會詢問；App 沒有 Apple 開發者簽章，macOS 把每個新版本當成新的 App，更新後可能會再問一次）。每個設備右邊的鈴鐺可以各自設定低電量通知：不通知，或低於 10%、15%、20%、30%、50% 時通知（預設 20%）。

### 更新頻率與省電模式

設定 → 更新頻率與省電：

- **更新頻率**：每秒（預設）、每 2 秒、每 5 秒、每 10 秒，電池、系統監控模組、耗電排行與 App 排行都依這個間隔取樣；越慢越省電
- **省電模式**：電力流向改用靜態圖示與箭頭（v1.0.0 的畫法），硬體細項的流帶與充電夥伴都不播放動畫，更新頻率至少每 2 秒。可以勾選「只在使用電池時啟用」（v1.7.1 起）：接上電源時自動恢復一般模式，拔掉電源再進入省電

## 安裝

1. 從 Releases 下載上面表格裡對應的 zip，解壓縮
2. 把 App（Finder 顯示「電池與系統監控」，檔名是 `macbookBatteryMonitor.app`）拖到「應用程式」資料夾
3. 第一次打開時 macOS 會擋下來（App 沒有 Apple 開發者簽章）。任選一種方式放行：
   - 到「系統設定 → 隱私權與安全性」，在下方找到這個 App，按「強制打開」
   - 或在終端機執行：
     ```bash
     xattr -dr com.apple.quarantine /Applications/macbookBatteryMonitor.app
     ```
4. 第一次啟動（v1.7.1 起）會詢問要「只看電池」還是「電池＋系統監控」（桌上型 Mac 是「只看耗電」／「耗電＋系統監控」）、要不要開啟管理員 CPU 取樣（Apple 晶片），以及通知與藍牙權限（藍牙只用來讀取羅技、Razer 等藍牙滑鼠、鍵盤的電量），並自動加入開機自啟動（可在設定關閉；macOS 13 用新版覆蓋後系統會清掉登錄，App 會自動再加一次）

已經在用 v1.5.0 以後的版本：到設定 → 更新按「一鍵更新」即可升級，不必重新下載。設定頁最下方會顯示 App 名稱與版本號。

## 功能

**選單列**（設定 → 選單列 → 顯示方式）
- 圖示 + 百分比、只有圖示、只有百分比、圖示 + 剩餘時間
- 圖示內百分比 + 剩餘時間（v1.2 起）：電量顯示在電池圖示裡，右側是剩餘／充滿時間；沒有時間資料顯示「—」，滿電、接電未充電、到達上限時分別顯示「已充飽」、「接電」、「已達上限」
- 充電中顯示閃電、接電未充電顯示插頭、低電量變紅

**面板**
- 電量、充放電狀態、剩餘時間／充滿時間（有充電上限時顯示充到上限的時間）
- 智慧充電（v1.7.1 起，支援調整充電上限的 Mac）：充電上限滑桿左邊是充電夥伴或電量條，滑桿下方是排程狀態（等待開始、充電中、已準備好等），點夥伴或狀態打開智慧充電頁。不支援的 MacBook 只顯示充電夥伴與「不支援智慧充電」的說明，點一下可以換外觀

## 智慧充電（v1.7.1 起）

需要能從 App 調整充電上限的 Mac（Apple 晶片的 MacBook，系統設定 → 電池裡有「充電上限」）；不支援的 Mac 沒有智慧充電，面板上方只顯示充電夥伴。

**怎麼運作**

1. 點充電上限滑桿左邊的充電夥伴（或滑桿下方的狀態），選「1 小時後」、「2 小時後」、「3 小時後」、指定完成時間，或勾選星期與時間儲存每週排程（例如上班日 8:00）。按之前每個選項旁邊就會依目前電量與充電速度預估：來得及顯示「可準時充到 95%：先維持 80%，約 8:07 開始充」，電量已接近目標時顯示「會直接充到 95%」，來不及顯示「來不及充到 100%，預計最多約 90%」（例如從 80% 充到 100% 通常要 1 個多小時，選 1 小時一定來不及）
2. 等待期間，App 把 macOS 的充電上限設成「保養上限」（預設 80%）。電量已經高於保養上限時不會把上限降到電量以下（降下去 macOS 會先讓電池放電到保養上限再充回來，白白多一次充放電），而是維持在目前的電量（進位到 5% 一格，例如 93% 時維持 95%）
3. 依需要的充電時間往前推算開始時間：有正在充電的速度就用它，沒有就用最近七天實際充電速度的中位數，再沒有就以每小時 20% 估算；80% 以上充電會變慢，這一段的時間乘上 1.8；另外預留 15 分鐘緩衝
4. 到了開始時間，把充電上限提高到「完成目標」（預設是原本的上限，也就是建立排程時系統設定的充電上限；需要 100% 時另外選），由 macOS 自己充電。開始之後即使估算時間變短，也不會把上限降回去，避免充到一半停下來
5. 充好時發一則「已充到目標」的通知；一次性的排程在拔掉電源後（或完成時間過了 2 小時還沒拔）還原原本的充電上限，每週排程則換到下一次
6. 照目前速度趕不上完成時間時，狀態顯示「可能無法準時」並通知一次，仍會繼續充電

完成目標、保養上限在智慧充電頁的「目標與保養上限」設定，套用到之後建立的排程。完成目標預設是「原本的上限」：充好後就停在平常的上限，不會多充到 100%。

**你自己調整時以你為準**：排程進行中，在面板拖動充電上限滑桿、或在系統設定改了充電上限，App 會結束排程，不會再改回去，也不會還原。取消排程（智慧充電頁的「取消排程並還原」）則會還原成建立排程前的上限。

**每次寫入都會確認**：寫入後讀回系統的上限，讀回的值等於目標才算成功；失敗時 1 分鐘後重試，還原失敗也會保留排程、稍後再試。

**睡眠時**（智慧充電頁的「睡眠時」）：

- **優先準時完成**（預設）：Mac 睡著時 App 無法準時提高上限，所以睡眠前若還在等待，會先把上限提高到目標，讓 macOS 在睡眠中充好（可能比預定時間早充滿）；醒來時如果還沒到開始時間，再降回保養上限。睡眠前最多等 5 秒讓寫入完成
- **精準喚醒**：在該開始充電前 1 分鐘叫醒 Mac，醒來就把上限提高到目標（被叫醒的 Mac 可能十幾秒就又睡回去，不等到開始時間），等待期間一直維持保養上限。只有還在等待時才排喚醒，已經充好或沒接電源時不會白白叫醒 Mac；已經排好的喚醒就算 Wi-Fi、藍牙的維護喚醒剛好在前幾秒發生也會保留。需要管理員授權一次，安裝與「管理員 CPU 取樣」共用的系統服務；喚醒事件的識別碼固定為 `com.kuan.batterymonitor.charging`（`pmset -g sched` 看得到），服務只接受 1 分鐘後到 7 天內的一個時間。授權取消、服務無法使用時自動改回「優先準時完成」。v1.7.1 以前安裝的服務只有 CPU 取樣，第一次選精準喚醒時會重新安裝；CPU 取樣照常運作，不需要重新授權

**限制**：實際充電仍由 macOS 控制，溫度保護、「最佳化電池充電」等系統機制可能讓充電暫停（狀態顯示「macOS 暫停充電」），不保證一定準時充滿。

**紀錄**：每次狀態變化、寫入上限與系統讀回的結果、睡眠與喚醒、喚醒排程都記在 `~/Library/Logs/macbookBatteryMonitor/charging-plan.log`（只存在這台 Mac，超過 256 KB 只留後半）。`macbookBatteryMonitor --charging-plan-status`（見「開發」）會印出目前的排程、系統充電上限、電量、排定的喚醒事件與最近的紀錄，不會改動任何設定。

**充電夥伴**：智慧充電頁最上方（或設定 → 充電上限）的「滑桿旁顯示」可以切換三種（不能調整充電上限的 Mac 叫「面板上方顯示」）：

- **充電夥伴（貓咪，預設）**：6 秒循環、透明背景的 HEVC 動畫：肚子呼吸起伏、尾巴偶爾慢慢掃一下、尾巴尖輕彈、垂下的前腳偶爾晃一下；充電時躺在發光的充電墊上、上方有充電波紋，等待時旁邊有睡覺的標示，充好時有打勾。只在面板開著時播放，面板關閉、省電模式、系統開了「減少動態效果」，或沒有 HEVC 硬體解碼的 Mac（例如 2015 年的 Intel 機型）顯示靜態圖
- **電池夥伴**：有表情的電池，裡面的底色是目前的電量；沒有排程時面無表情、等待時閉眼睡覺、充電中微笑、充好時大笑、可能延遲或系統暫停時皺眉，面板開著時偶爾眨眼
- **電力流動**：電量條，充電中有光點往右流

## 一鍵更新

設定 → 更新可以檢查 GitHub 上的新版本，有新版時按「一鍵更新」：

1. 下載通用版的 zip（舊系統版本下載 `…-macOS12.zip`，系統已是 macOS 14 以上時改下載通用版；舊版 Release 沒有通用版時改用舊檔名的 zip），只從 `github.com` 與 `githubusercontent.com` 下載
2. 驗證：比對 Release 附的 `SHA256SUMS.txt`，並確認 App 的識別碼、版本號、Beta 序號與簽章
3. App 結束後換上新版並重新開啟；換不過去會放回原本的版本。設定、電量歷史、智慧充電排程與自訂的 App 圖示顏色都會保留；下載或驗證失敗、或更新中途被中斷時，暫存檔會清掉

「自動檢查更新」預設開啟：啟動後與之後每 6 小時看一次，距離上次檢查超過一天才會連到 `api.github.com`，只提示、不會自動安裝。所以一直開著 App 的話，新版發布後大約 1 天內會發現。

「有新版本時通知」預設開啟（v1.7.1 起）：自動檢查發現新的正式版時發一則 macOS 通知，每個版本只通知一次，點通知會打開設定並捲到「更新」。不想收到可在設定 → 更新關閉。App 不在可寫入的位置（例如由系統管理員安裝）時無法一鍵更新，會提示到 GitHub 手動下載。

**Beta 測試版**（v1.7.1 起）：GitHub 上標成「預先發行版本」的 Beta（例如 v1.8.0-beta.1）只有在設定 → 更新按「檢查更新」時才會列出，自動檢查不會提示、面板底部不會出現、也不會發通知。按「安裝 Beta…」後會先說明測試版可能不穩定，再按一次「安裝 Beta」才會下載安裝（同樣驗證校驗碼與簽章）。已有比 Beta 新的正式版時只會列出正式版；裝了 Beta 之後，下一個 Beta 一樣要手動檢查，正式版則照常提示與通知。想回到正式版，到 GitHub 下載正式版重新安裝即可。

v1.4.1 以前的版本沒有一鍵更新，要先手動下載一次新版。

## 管理員 CPU 取樣（選用，預設關閉）

部分機型（例如下表的 M1、M2 Pro）的 CPU 能量計數不更新，晶片細項的 CPU 只能顯示 0 W。需要 CPU 功耗時，可以在設定 → CPU 功耗打開「管理員 CPU 取樣」，改用系統內建的 `powermetrics` 讀取。不需要的話維持關閉即可。

- **開啟**：第一次啟動時會詢問，之後只有在設定裡親手打開時才會跳出 macOS 的管理員授權視窗，安裝一個系統服務；不儲存密碼、不修改 sudoers。授權取消或失敗時選項會自動關回去，開 App 或開機時不會跳出密碼視窗
- **取樣**：只在主面板開著時連線，間隔與其他資訊相同（依更新頻率）。關閉面板、進入設定頁、睡眠或結束 App 就斷線，`powermetrics` 立即停止；服務閒置 30 秒後自行結束，不常駐
- **關閉**：關掉選項就停止並移除服務（不需要密碼）；智慧充電的精準喚醒也在使用時只斷線、不移除，兩個都關掉才移除
- **耗電**：只有主面板開著時 `powermetrics` 才會執行。M1 MacBook Air 實測，面板開著時服務與 `powermetrics` 合計另佔 CPU 約 1%（省電模式約 0.3%）；面板關閉時與沒開這個選項相同
- **安全**：服務只接受安裝時那位使用者的連線，只能開始／停止固定參數的 `powermetrics`（間隔只能是 1、2、5、10 秒）、排定或取消一個固定識別碼且限定時間範圍的智慧充電喚醒，或移除自己；不接受任意指令、路徑或 PID
- **位置**：服務程式在 `/Library/PrivilegedHelperTools/com.kuan.batterymonitor.cpu/`，啟動設定在 `/Library/LaunchDaemons/com.kuan.batterymonitor.cpu.plist`

等待授權、尚未取得資料或資料逾時時不顯示舊值；系統功耗與 CPU 的取樣時間窗只是近似同步。

## 電力總覽與硬體功耗（v1.2 起）

面板主頁依更新頻率（預設每秒）取樣，關閉面板、進入設定頁或睡眠時停止取樣。讀取不需要管理員權限（CPU 改用 `powermetrics` 的選用功能除外）。

**接著電源時的穩定顯示**

- **是否在充電**：電池晶片回報的「充電中」旗標會停在舊值（實測 M1 在約 14 W 充入電池、電量持續上升時，仍有十幾秒回報「未充電、電流 0」），所以有 SMC 即時功率時以功率為準：充入 3 W 以上算充電、0.5 W 以下算沒在充，中間才看晶片旗標。到達充電上限後要晶片旗標與功率都同意才算充電。Intel 快要充滿、充電電流很小時，SMC 推算的電池功率會是小負值（2015 MacBook Air 實測 86% 時 -3 W），電池晶片明確回報在充電、電流是正的時候以晶片為準，不會誤顯示「供電不足」
- **狀態確認 10 秒**：接著電源時，充電中／已達上限／未充電之間的切換要持續 10 秒才更新，避免 macOS 在上限附近反覆暫停、恢復充電時圖示跟著跳；實際拔除或重新接上電源立即更新
- **滿電緩衝**（沒有設定系統充電上限時）：畫面優先維持「已充飽」，短暫降到 99%／98% 仍保留滿電狀態，低於 98% 恢復一般判定
- **流向圖跟著狀態**：接著電源但沒在充電（滿電、到達上限、暫停）時，電池功率在 ±2 W 內顯示由變壓器直接供電，流向變化持續 10 秒才切換；滿電時「電力流向」標題列會顯示即時帶正負號的電池功率。供電不足或電量高於上限、電池正在放電時照實畫出電池一起供電，剩餘時間與低電量提醒不受影響
- **預估時間一致**：有充電上限時，右上角與詳細資訊的「系統預估」都是充到上限的時間
- **剛插電**（v1.7.1 起）：Intel 的充電器要十幾秒才開始充電，這段期間電池可能還在放電。插上電源後 30 秒內說明改成「剛接上電源」，選單列不顯示剩餘時間，流向圖先不畫電池供電；從電池一起供電轉成充電時立即切換，電池那條也不會出現負瓦數
- **剛開始充電、剛拔電的時間**（v1.7.1 起）：剛開始充電的頭一分鐘電流還在爬升，平均充電電流顯示「計算中…」。macOS 還在估算充滿時間時，右上角與充電預估也顯示「計算中…」，不自己用直線推算（沒考慮 80% 以上電流變小，Intel 實測 70% 時算出 37 分、macOS 是 80 分以上）。macOS 還在估算剩餘時間時，「系統預估」顯示「計算中…」，不改用電池晶片的平均值（剛拔電時平均電流還沒跟上，Intel 實測會算出 12 小時以上），右上角改用依目前耗電的估算；Intel 剛拔電的頭一分鐘放電電流偏低，也先不納入平均，否則剩餘時間會一直往下掉

**電力總覽**（變壓器、系統、電池）

- **變壓器輸入**讀 SMC `PDTR`，**系統耗電**讀 SMC `PSTR`
- **電池功率**用「變壓器輸入 − 系統耗電」推算，所以三個數字一定對得起來。實測兩個感測器都每秒更新一次，但 `PSTR` 比 `PDTR` 慢一次更新，同時讀的兩個值直接相減會有約 ±4 W 的雜訊；所以系統耗電配對 1 秒前讀到的變壓器輸入。更新頻率慢於每秒時，在每次更新前 1 秒先讀一次變壓器輸入，電池閒置時誤差由約 4 W 降到 0.00 W。SMC 的 `PPBR` 在部分機型上與實際充放電功率不符，所以完全不使用；缺少 `PDTR` 或 `PSTR` 時，改用 IORegistry 電壓 × 電流備援
- 剛拔電時 `PDTR` 可能殘留舊值，只在系統確認接電時才計入輸入
- macOS 放電到充電上限時會暫停變壓器供電，此時仍視為接電，顯示「已達充電上限」
- SMC 數值即時更新，不會像電池晶片（IORegistry）那樣插拔後延遲約一分鐘。插拔通知後會在 1、3、6 秒各重讀一次

**硬體細項**

- **系統總功耗**：優先讀取 SMC `PSTR`，不可用時退回 IORegistry 的 `SystemLoad`
- **螢幕背光**：讀取 SMC 感測器（`PDBR`／`PBwo`）。沒有這兩個 key 的機型（例如 M1 MacBook Air）不顯示背光，背光改算在「其他（含螢幕）」裡
- **CPU／GPU／ANE**：IOReport Energy Model 的能量差除以實際取樣時間；首次取樣只建立基準。Energy Model 沒有 ANE 通道的機型不顯示 ANE
- **其他（估算）**：總功耗扣掉背光與已取得的晶片功耗後的差值；缺晶片細項時改標示「未分類（估算）」
- 晶片合計只涵蓋取得的 CPU、GPU、ANE，不代表完整 SoC 功耗，也不含外接螢幕
- 每一項都可以在設定 → 顯示項目隱藏；隱藏「晶片運算」後就不能再展開 CPU／GPU／ANE

IOReport 是系統私有介面，可用性依晶片與 macOS 版本而異。機型本身沒有的項目自動隱藏，暫時讀不到的項目顯示「—」：

| 機型 | 系統總功耗 | 背光 | GPU | CPU | ANE |
|---|---|---|---|---|---|
| M2 Pro | ✓ | ✓ | ✓ | 顯示 0 W（通道未持續更新）；開啟管理員 CPU 取樣可讀到 | 閒置時 0 W |
| M1 MacBook Air | ✓ | 沒有感測器，自動隱藏（算在「其他（含螢幕）」） | ✓ | 顯示 0 W（通道未持續更新）；開啟管理員 CPU 取樣可讀到 | 沒有通道，自動隱藏 |

## 更新頻率與省電設計

所有即時資訊預設每 1 秒更新（可改成 2／5／10 秒；省電模式至少 2 秒），但每次只做必要的讀取。M1 MacBook Air 實測：

| 情況 | 每秒更新 | 省電模式（每 2 秒） |
|---|---|---|
| 面板關閉，只看電池（系統監控總開關關閉） | 約 0.2% | 約 0.15% |
| 面板關閉，四個系統監控模組全開 | 約 1% | 約 0.5% |
| 打開電池面板（耗電排行分頁） | 約 4%，`top` 另佔約 6% | 約 2%，`top` 另佔約 3% |
| 打開 CPU 或記憶體模組面板 | 約 3%，`top` 另佔約 6% | 約 2%，`top` 另佔約 3% |

`top` 只在耗電排行分頁或 CPU／記憶體面板開著時執行，切到其他分頁或關閉面板就停止。

- 面板關著時依更新頻率更新選單列需要的資料（電量、狀態、功率、剩餘時間）；插拔電源另由系統通知立即更新
- 選單列圖示只有在數字、時間或狀態改變時才重畫
- SMC 每個 key 的格式查過一次就記住，之後每個數值只需一次 SMC 呼叫；每秒只讀 `PDTR`、`PSTR` 兩個值
- 變壓器規格接上電源後每 30 秒查一次；系統的充電上限設定只在啟動、打開面板與系統通知有變更時讀取，不每秒查詢
- 智慧充電每次更新只做判斷（沒有排程時不做任何事），需要改上限時才呼叫系統；精準喚醒的服務只在排定或取消喚醒時連線
- 充電夥伴的動畫是硬體解碼的小尺寸影片（152×160 像素），只在面板開著時播放；沒有 HEVC 硬體解碼的 Mac 改用靜態圖，不用 CPU 解碼
- 面板每次打開才建立，關閉就連同視窗整個釋放，背景沒有任何畫面在更新
- 硬體細項與 SMC 溫度只在面板開著時讀；選用的管理員 CPU 取樣也只在主面板開著時連線
- 流向動畫與電量條的光點由 Core Animation 合成（不逐幀更新 SwiftUI），只在面板開著且該線路有供電時播放；支援「減少動態效果」；省電模式完全不播放動畫
- 系統監控只取樣有開啟的模組；總開關關閉時完全不建立模組的圖示與計時器；選單列圖示寬度固定
- 磁碟容量每秒用 `statfs()` 讀，系統可清出的空間每 5 分鐘校正一次；網路只查目前使用中的介面；外接磁碟清單用 `getfsstat(MNT_NOWAIT)`，不會被離線的網路磁碟卡住
- SMART 健康狀態要啟動 `diskutil`，還可能喚醒休眠中的外接硬碟，所以只在磁碟面板開著時查，每顆最多 10 分鐘一次
- 風扇與溫度只在 CPU 面板開著時於背景每 2 秒讀一次，選單列平常不讀
- 周邊設備電量每 60 秒查一次：鍵盤、滑鼠、觸控板讀 IORegistry；耳機要跑 `system_profiler`，所以背景更新時只有連著藍牙音訊裝置才查；藍牙低功耗設備用 CoreBluetooth 向已連線的設備讀電量，不建立新連線
- 電量歷史每分鐘記一筆（每 15 分鐘寫一次檔，睡眠前和結束時也會存）；健康度每 6 小時查一次

## 資料來源

| 項目 | 來源 |
|---|---|
| 電量、電壓、原始電流、容量、循環次數 | IORegistry `AppleSmartBattery` |
| 外部輸入、系統功耗、背光 | SMC（唯讀，`PDTR`、`PSTR`、`PDBR`／`PBwo`）；桌上型 Mac 只讀 `PSTR`（整機耗電） |
| 變壓器即時電壓、電流 | SMC（唯讀，`VD0R`、`ID0R`）；沒有時用 IORegistry `PowerTelemetryData` 的 `SystemCurrentIn` |
| 電池功率 | 由「外部輸入 − 系統功耗」推算；缺少任一路時改用 IORegistry 電壓 × 電流（不使用 `PPBR`） |
| CPU／GPU／ANE 功耗 | Apple 晶片：IOReport Energy Model，管理員模式的 CPU 改用 `powermetrics`；Intel：SMC `PCPC`／`PCPG`（唯讀） |
| 系統預估時間 | IOKit Power Sources |
| 是否在充電 | SMC 即時電池功率為主，數值模糊時看 IOKit Power Sources／IORegistry 的充電旗標 |
| 健康度（最大容量）、電池狀況 | `system_profiler SPPowerDataType` |
| 電池溫度（詳細資訊） | SMC（唯讀，`TB0T`～`TB2T`） |
| 耗電排行 | `top -o power` |
| 歷史回填、拔電時間 | `pmset -g log` |
| 充電上限（設定值、滑桿與智慧充電的調整） | macOS 的充電上限服務（PowerUI 的 `PowerUISmartChargeClient`，系統設定的電池頁也是用它）；變更通知 `com.apple.powerui.mclstatuschanged`。不需要管理員權限 |
| 充電上限（目前生效中） | `/Library/Preferences/com.apple.powerd.charging.plist`（唯讀；只在接電時存在） |
| 智慧充電的充電速度 | 正在充電時的平均電流；沒有時用電量歷史最近七天的充電速度中位數 |
| 智慧充電的精準喚醒 | 管理員服務以 IOKit `IOPMSchedulePowerEvent` 排定 `wake` 事件（識別碼 `com.kuan.batterymonitor.charging`） |
| 睡眠前的寫入 | IOKit 系統電源通知（`IORegisterForSystemPower`），最多延後睡眠 5 秒 |
| 今日回顧 | 電量歷史（每分鐘一筆） |
| CPU 使用率、各核心 | `host_processor_info` 的累計 tick 差值；核心類型來自 `hw.perflevel0／1` |
| 平均負載 | `getloadavg` |
| GPU 使用率、GPU 記憶體 | IORegistry `IOAccelerator` 的 `PerformanceStatistics`（Intel 內顯的記憶體是 `inUseSysMemoryBytes`） |
| 記憶體組成、壓力、Swap | `host_statistics64`、`kern.memorystatus_vm_pressure_level`、`vm.swapusage` |
| 磁碟容量 | `statfs()`，加上定期校正的系統可清出空間（與 Finder 一致） |
| 磁碟讀寫 | IORegistry `IOBlockStorageDriver` 的累計讀寫位元組 |
| 外接磁碟清單、連線類型 | `getfsstat`、DiskArbitration（`DeviceInternal`、`DeviceProtocol`） |
| 磁碟健康狀態 | `diskutil info -plist` 的 `SMARTStatus` |
| 風扇轉速 | SMC（唯讀，`F<n>Ac`、`F<n>Mn`、`F<n>Mx`） |
| CPU 面板的溫度 | IOHIDEventSystem 溫度感測器（私有介面，不存在時不顯示）；M2 系列改讀 SMC 核心溫度鍵；Intel 讀 SMC 的核心、PECI／die／proximity、內顯、SSD、電池等鍵 |
| 網路速度與累計流量 | `sysctl` 的 64 位元介面計數器（`NET_RT_IFLIST2`），只查目前使用中的介面 |
| 網路介面與 IP | `SCDynamicStore`（預設路由介面）、`getifaddrs` |
| CPU／記憶體 App 排行 | `top -o cpu`、`top -o mem` |
| 新版本資訊（一鍵更新） | GitHub API `releases`（最近 20 個；Beta 只在手動檢查時列出），自動檢查每天最多一次；下載檔以 Release 的 `SHA256SUMS.txt` 驗證 |
| 周邊設備電量（鍵盤、滑鼠、觸控板） | IORegistry 中帶 `BatteryPercent` 的服務 |
| 周邊設備電量（藍牙低功耗滑鼠、鍵盤） | CoreBluetooth：已連線設備標準電池服務（`0x180F`）的電池電量（`0x2A19`），需要藍牙權限；名稱看不出是滑鼠或鍵盤時用 IORegistry 的 HID 用途判斷 |
| 周邊設備電量（耳機左右耳、充電盒） | `system_profiler SPBluetoothDataType`；是否連著藍牙耳機由 CoreAudio 的裝置清單判斷 |

- 歷史紀錄：`~/Library/Application Support/BatteryMonitor/history.json`（保留 7 天）
- 設定與智慧充電排程：`com.kuan.batterymonitor`（UserDefaults）
- 智慧充電紀錄：`~/Library/Logs/macbookBatteryMonitor/charging-plan.log`
- 管理員服務（只在開啟管理員 CPU 取樣或精準喚醒時存在）：`/Library/PrivilegedHelperTools/com.kuan.batterymonitor.cpu/`、`/Library/LaunchDaemons/com.kuan.batterymonitor.cpu.plist`

## 解除安裝

1. 有設定智慧充電的話，先在智慧充電頁按「取消排程並還原」，把充電上限還原
2. 在 App 設定裡關閉「管理員 CPU 取樣」、把智慧充電的「睡眠時」改回「優先準時完成」（有開過的話，會移除系統服務），並關閉「開機時自動啟動」，然後結束 App
3. 刪除 `/Applications/macbookBatteryMonitor.app`
4. 如果先刪了 App、系統服務還留著，在終端機執行：
   ```bash
   sudo launchctl bootout system/com.kuan.batterymonitor.cpu
   sudo rm -f /Library/LaunchDaemons/com.kuan.batterymonitor.cpu.plist
   sudo rm -rf /Library/PrivilegedHelperTools/com.kuan.batterymonitor.cpu
   ```
5. （選擇性）清除資料：
   ```bash
   rm -rf ~/Library/Application\ Support/BatteryMonitor ~/Library/Logs/macbookBatteryMonitor
   defaults delete com.kuan.batterymonitor
   ```

- 舊系統版本（macOS 12 起）在 `legacy-macos12` 分支：把 macOS 13／14 才有的寫法（Observation、Swift Charts、Grid、SMAppService 等）換成相容寫法，其他程式與主分支相同。在較新的系統上加 `--macos12-paths` 啟動，可以強制走 macOS 12 的寫法測試。發布時，`legacy-macos12` 分支的版本號（含 Beta 序號）和這次發布相同，GitHub Actions 才會一起打包 `…-macOS12.zip`
- `build.sh` 會一次編出 Apple 晶片與 Intel 兩種架構（通用版）；只裝 Command Line Tools、無法一次編兩種架構時，自動改編這台電腦的架構
- 發布時 GitHub Actions 會打包三個 zip：通用版（`MBMEdition=universal`），以及給 v1.5.0～v1.6.2 一鍵更新用的舊檔名 `battery`／`status` zip（內容相同，只有 `MBMEdition` 不同，用來決定從舊版升級時系統監控預設開或關）
- Info.plist 帶 `MBMPrerelease`（例如 `beta.1`）時，發布的 tag 是 `v<版本>-beta.1`，自動標成預先發行版本，不會變成「最新版本」
- `build.sh` 會把管理員服務程式（`CPUPowerHelper`）放進 App 的 `Contents/Library/Helpers/`，充電夥伴的動畫與靜態圖（`Resources/Companion/`）放進 `Contents/Resources/`；服務只有使用者開啟管理員 CPU 取樣或精準喚醒時才會安裝到系統
- 只裝 Command Line Tools 時沒有 SwiftUI 的 macro 外掛，所以程式裡不用 `@State`，介面狀態集中在 `PanelState`

App 圖示由 `Scripts/make-icon.swift` 產生：貓咪是 `Resources/icon-cat.png`（照片去背），充電墊、波紋與背景用程式畫出來。

```bash
swiftc -O Scripts/make-icon.swift -o build/make-icon
build/make-icon Resources/AppIcon.icns                                  # 內建的薄荷綠圖示
for bg in peach night sky; do build/make-icon --bg $bg --size 512 --preview Resources/AppIcons/icon-$bg.png; done
```
